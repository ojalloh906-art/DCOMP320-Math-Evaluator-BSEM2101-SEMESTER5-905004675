# DCOMP320 - Stacks Implementation

## Project Overview
This Python project reads mathematical expressions from `input.txt`, evaluates each expression using stack-based algorithms, and writes the results to `output.txt` while preserving separator lines.

## Requirements
- Python 3.9 or later
- No third-party packages are required

## Files
- `stack_evaluator.py` - main Python source code
- `input.txt` - sample mathematical expressions
- `output.txt` - results generated by the program
- `test_stack_evaluator.py` - automated tests
- `test_results.txt` - captured automated test results

## Supported Syntax
The evaluator supports numbers, parentheses, and the operators `+`, `-`, `*`, `/`, and `**`. Standard operator precedence is observed and exponentiation is right-associative.

## How to Run
Place `stack_evaluator.py` and `input.txt` in the same folder. Open a terminal in that folder and run:

```bash
python stack_evaluator.py
```

The program creates or replaces `output.txt` with the evaluated results.

## Input Format
Write one expression per line. Separate expressions with a line made only of hyphens, for example:

```text
3 + 5 * 2
-----
(8 / 4) + 7 * 2
```

## Output Format
Each expression is replaced by its result, and separator lines are preserved:

```text
13
-----
16
```

## Testing
Run the automated test suite with:

```bash
python -m unittest -v test_stack_evaluator.py
```

## Design Notes
The program uses a custom `Stack` class with `push`, `pop`, `peek`, `is_empty`, and `size`. It tokenizes infix expressions, converts them to postfix notation using the Shunting Yard approach and an operator stack, then evaluates the postfix expression with a second stack.

## Assumptions and Limitations
- Input is expected to contain valid arithmetic expressions or separator lines.
- Unary negative numbers such as `-5 + 2` are not supported in this version; subtraction such as `0 - 5 + 2` is supported.
- Variables and mathematical functions such as `sin()` are outside the assignment scope.
- Division by zero and malformed expressions are written as `ERROR: ...` rather than stopping the whole file-processing run.
